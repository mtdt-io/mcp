# Publishing the MTDT connector and plugin

This folder contains submission inputs and packaging tools. Project work and decisions are
tracked in the MTDT workspace through `tt` (preparation #1323, saved-config refresh #1982).
Reviewer credentials belong in the portals' private forms, never in this repository or ZIPs.

## Build and check the packages

Python 3 and its standard library are sufficient:

```bash
python3 publishing/package.py build
python3 publishing/package.py check
python3 publishing/package.py preflight --output dist/public-preflight.json
```

`dist/` is ignored by git. The build produces two minimal, deterministic ZIPs and SHA-256
checksums. The OpenAI archive contains `.codex-plugin/plugin.json`, a URL-only `.mcp.json`,
the two skills, README, CONNECT and the icon. The Claude archive contains
`.claude-plugin/plugin.json` and `.mcp.json` with `type: http`. LICENSE is included when present.
Submission source JSON, reviewer setup instructions, evidence, scripts, registry files and
marketplace catalogs are excluded from both ZIPs. The two MCP configurations are deliberately
built from the same endpoint with each host's documented format.

The maintained OpenAI manifest is `publishing/openai-plugin.json`; the build installs it in
the ZIP's native location and imports `review-cases.json` into `extensions.com.openai.review`.
Do not change the published official registry's `server.json` just to match a plugin version.
The registry release and the plugin package are separate artifacts.

`check` verifies file paths, text limits, skill frontmatter, tool names used in review cases,
the single hosted MCP endpoint, image dimensions, version alignment and ZIP contents. These
are local structural checks, not a directory approval or an end-to-end test of the service.
`preflight` makes unauthenticated GETs to public pages and OAuth metadata. It reports missing
review evidence and directory prerequisites separately from package validity; use
`--require-ready` to return a failing exit code while those prerequisites remain unresolved.
Use `--tools-json /path/to/export.json` to inspect a fresh tools/list export. That option does
not turn a local inventory into proof that every tool was exercised.

The maintained inventory contains 32 tools from the local server source and is marked
`live: false`. It includes saved composition get/add/remove and the read-only run preview.
The review cases follow browse → save → inspect → preflight → preview → launch by ID;
launch tools no longer accept inline composition or Flow activation arguments. After rolling
out the matching MCP build, compare a fresh live tools/list before submission. The versioned
justifications must cover exactly the same tool names as the inventory.

## OpenAI / Codex directory

Open [Plugins](https://platform.openai.com/plugins) with the owning OpenAI organization and
project. The submitter needs the appropriate management role and verified publishing identity.
Upload the generated `mtdt-openai-<version>.zip` with MCP included in the initial package.

Use the imported listing, five positive and three negative cases and release notes. Confirm
the category and publisher shown by the portal. Connect the MCP via OAuth, perform the
portal's domain-ownership challenge, inspect package/tool checks, and resolve required issues.
Use `tool-justifications.json` for draft explanations of each tool's annotations, comparing
them with the scan and actual behavior. Explain all three hints for every tool in the portal;
justifications do not replace or change server-provided hints.
The challenge value is generated by the portal; do not invent it or bundle it in the plugin.
If requested, serve its exact plain text at the portal-specified host's
`/.well-known/openai-apps-challenge` path through the normal deployment process.
If that path already carries another plugin's challenge, choose an allowed parent origin or
another eligible host as directed by the portal instead of replacing its token.

Configure OAuth DCR against the advertised Keycloak issuer. During rehearsal, check the exact
redirect URI supplied by the OpenAI portal, the resource/audience value and token refresh.
For workspace email-domain restrictions, confirm `openid` and `email` are enabled on the
registered client and that UserInfo returns a verified email. Discovery alone cannot prove
the returned user's claims. Do not assume the local coding-client login proves ChatGPT login.

Fill Review details with the dedicated account, workspace, login instructions and an accessible
recording URL. Follow [REVIEWER-SETUP.md](REVIEWER-SETUP.md) and [DEMO-SCRIPT.md](DEMO-SCRIPT.md).
Provide the demo URL in the portal, or build with
`python3 publishing/package.py build --demo-url https://your-owned-host/actual-recording`.
No placeholder recording URL is included. Run every case with the reviewer account before
submission. Then submit the draft; publication is a separate action after approval.

## Claude connector directory

Open [Directory management](https://claude.ai/directory/manage), select Submit new → MCP
connector and use `publishing/claude-connector.json` as copyable form inputs. It is a worksheet,
not an API request or an import schema. Tools sync from the hosted server. Pick the portal's
actual categories and check the permanent slug before submitting.

Use the universal URL and OAuth DCR, then enter listing/use-case/company information, data
handling answers, reviewer access and the policy attestations. Confirm draft data-handling
answers against the service's actual use and published policies. Exercise every exposed tool
through MCP Inspector and a custom connector in Claude before making the testing attestation.

Claude's current checklist asks for `destructiveHint: true` on modifying tools. The inventory
checker reports stateful tools with both readOnlyHint and destructiveHint false. The inventory
shipped in this folder comes from local source, not the live endpoint. Compare a fresh live
tools/list before asserting catalog compliance. Do not mark an additive tool
read-only just to silence a catalog warning.

MTDT exposes tools without an MCP App UI. No carousel screenshots are supplied. A demo
recording for OpenAI can still be prepared with real tool interactions.

## Claude plugin bundle

For the connection plus bundled skills, also submit Plugin bundle in the same portal. Use
repository `mtdt-io/mcp`, plugin path at the root, and the reviewed branch or tag. The portal
reads GitHub; the local ZIP is useful for clean validation and is not the portal's source.
Push the reviewed preparation branch before validating it in the portal. Connect a GitHub
account with write access. A LICENSE file or a `license` manifest field is required for this
listing; the owner must choose it. Do not infer a license from the backend service's package.

Run Claude Code's local validator on the generated clean directory:

```bash
claude plugin validate dist/claude --strict
```

This avoids the CLI treating the root marketplace file as the validation target. Validate the
same commit in the portal, check README-derived listing and data handling, then submit the
bundle. Submit the hosted MCP connector separately even when the plugin points to it.
